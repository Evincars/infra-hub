Spring a JPA: tahák pro juniora

Příklady pocházejí z backendu Service Watcher (Java 21, Spring Boot 3). Tahák lze vytisknout přímo z prohlížeče.

Jak putuje požadavek

HTTP → MonitoredServiceController → MonitoredServiceManager → MonitoredServiceRepository → Hibernate → PostgreSQL

Controller řeší HTTP a DTO. Manager řeší aplikační operace a transakce. Repository poskytuje přístup k entitám. Hibernate převádí práci s entitami na SQL.

Slovníček s příklady

PojemCo znamená a kde ho najdu
BeanObjekt spravovaný Spring kontejnerem. Výchozí singleton znamená jeden objekt pro definici beanu v kontejneru. ClockConfig registruje hodiny pomocí @Bean.
@Configuration / @Bean Konfigurační třída / metoda, jejíž návratový objekt se registruje jako bean. Argumenty metody dodá Spring.
Dependency injectionObjekt dostane závislosti zvenku místo jejich vlastní konstrukce. Spring předá repository do konstruktoru manageru. Lombok @RequiredArgsConstructor tento konstruktor generuje pro neinicializovaná final pole (a požadovaná @NonNull pole).
@ServiceOznačí aplikační službu, kterou component scan zaregistruje jako bean. Například MonitoredServiceManager.
JPA / HibernateJPA je standard pro objektově-relační mapování. Hibernate je jeho implementace používaná v tomto projektu.
@EntityJava objekt mapovaný na databázový řádek, nikoli automaticky Spring bean. MonitoredService má @Id jako primární klíč a @Column pro mapování sloupců.
JpaRepository<MonitoredService, Long> Rozhraní s operacemi jako findById, save a delete. Typy znamenají entitu a její ID. Spring Data vytvoří implementaci za běhu; naše repository ji nemusí psát ručně.
@TransactionalUrčuje transakční hranici. Standardně se připojí k existující transakci, nebo otevře novou. Úspěšná transakce se potvrdí (commit); při RuntimeException nebo Error se standardně vrátí zpět (rollback). Checked výjimka standardně automatický rollback nevyvolá.
Dirty checkingHibernate sleduje spravovanou entitu uvnitř persistence contextu. Při flush zapíše změny. Proto manager v update po načtení a změně entity nemusí znovu volat save.
@RestController / DTOController vrací tělo HTTP odpovědi, zde JSON. DTO je datový objekt pro API, oddělený od entity. @RequestBody načte tělo požadavku a @Valid spustí validaci omezení na request DTO.

@param není @Param

/**
 * @param id ID služby, jejíž stav zapisujeme
 * @return počet změněných řádků
 */
@Transactional
@Modifying
@Query("update MonitoredService s set s.lastStatus = :status where s.id = :id")
int updateStatus(@Param("id") Long id, @Param("status") ServiceStatus status);

Ukázka je zkrácená: skutečná metoda zapisuje také čas kontroly. @param je Javadoc tag uvnitř komentáře: popisuje argument, ale nemění chování. @Param("id") je Spring Data anotace: sváže argument s :id v dotazu. @return dokumentuje návratovou hodnotu; @throws dokumentuje podmínku vyvolání výjimky.

@Query zde obsahuje JPQL (názvy entit a atributů), nikoli SQL (názvy tabulek a sloupců). @Modifying označuje měnící dotaz.

Časté chyby

readOnly = true je optimalizační pokyn, ne spolehlivý zákaz zápisu. Transakční proxy zachytí volání zvenku přes Spring bean; volání vlastní metody přes this samo novou transakci nezapne. new MonitoredServiceManager(...) v běžném unit testu také nemá Spring transakční proxy.

HTTP kontrola může dlouho čekat. PingService proto nedrží databázovou transakci během síťového volání; až výsledek uloží krátkým cíleným zápisem.
