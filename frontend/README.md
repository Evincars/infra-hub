# Service Watcher – Frontend

Vite + React 19 + TypeScript, TanStack Router (file-based), TanStack Query, Zustand, Tailwind CSS v4, shadcn/ui (Radix).

## Develop

```bash
npm install
npm run dev        # http://localhost:5173, proxies /api -> http://localhost:8080 (Spring Boot)
npm run build      # type-check + production build into dist/
npm run lint       # oxlint
```

Override the proxy target with `VITE_API_PROXY_TARGET`, the API base path with `VITE_API_BASE_URL` (see `.env.example`).

## How this project was scaffolded

```bash
npm create vite@latest frontend -- --template react-ts
cd frontend && npm install

npm install @tanstack/react-router @tanstack/react-query zustand
npm install -D @tanstack/router-plugin @tanstack/react-router-devtools @tanstack/react-query-devtools \
               tailwindcss @tailwindcss/vite

# Before shadcn init: add tanstackRouter() + tailwindcss() + the "@" alias to vite.config.ts,
# "paths": { "@/*": ["./src/*"] } to tsconfig.json and tsconfig.app.json,
# and replace src/index.css with:  @import "tailwindcss";
npx shadcn@latest init --template vite --base radix --preset nova
npx shadcn@latest add badge card table skeleton alert dropdown-menu
```

## Structure

```
src/
├── main.tsx                 # bootstrap: QueryClientProvider + RouterProvider
├── routeTree.gen.ts         # GENERATED by the router plugin, committed so `tsc` works in CI; don't edit
├── app/                     # app-wide wiring: query client defaults, router instance + context type
├── routes/                  # file-based routes: thin, only compose features (URL -> page)
├── features/<feature>/      # vertical slices, e.g. features/services
│   ├── api/                 #   HTTP calls + query keys/queryOptions
│   ├── hooks/               #   React Query hooks
│   ├── components/          #   feature-specific UI
│   ├── types.ts
│   └── index.ts             #   public API: import only from here
├── components/
│   ├── ui/                  # shadcn/ui primitives (owned code, add with `npx shadcn add`)
│   └── layout/              # app shell: header, error/not-found fallbacks
├── stores/                  # Zustand: client-only UI state (server state lives in React Query)
├── hooks/                   # shared, feature-agnostic hooks
├── lib/                     # framework-agnostic helpers: api client, formatting, cn()
└── config/                  # typed env access
```

Rules of thumb: features don't import each other's internals; `routes/` and `components/` may import features; `lib/` imports nothing app-specific.
